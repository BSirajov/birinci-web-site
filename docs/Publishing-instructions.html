Publishing changes to Birinci

Quick reference · 1 November 2026

Use this guide to publish future changes through the automatic deployment setup. Saving files locally does not publish them. Pushing reviewed changes to main starts the checks and deployment.

Website changesOffline app changesRemember

Publish website content and design changes

Use this route for stories, illustrations, translations, Help pages, and the main website. It updates both the online site and the offline app.

  1. Make and save your changes in C:\dev\birinci-web-site.
  2. Ask Codex: “Review these changes, commit them, and push to main.”
  3. GitHub runs QA automatically. If it passes, the workflow builds and publishes both editions.
  4. On the online Actions page, wait for Site QA and Publish online and offline runtimes to turn green. Open Actions
  5. Open the online site and the offline app, then check the pages and illustrations you changed.

Publish changes to the offline app

Use this route for the download interface, offline storage, or other features specific to the offline app.

  1. Make and save your changes in C:\dev\birinci-offline.
  2. Ask Codex: “Review the offline changes, commit them, and push to main.”
  3. On the offline Actions page, wait for Offline QA and deployment to turn green. Sign in to GitHub to view this private repository. Open Actions
  4. Check the offline app. This workflow updates only /offline/ and leaves the online site unchanged.

Remember

  • Keep Hostinger’s Git auto-deployment off. Do not use its Redeploy button.
  • If a workflow fails, ask Codex to investigate before retrying. Do not upload the repository manually.
  • Existing offline users should connect to the internet, open the offline app, and update any downloaded language packs marked as having an update available.
  • USB release packages are built separately. These workflows publish the online website and the offline PWA.
  • Only validated runtime files are published. Word documents, authoring material, temporary files, and deployment archives stay out of the public website.
